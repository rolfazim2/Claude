# Gram — корпоративный мессенджер (аналог Telegram)

Полнофункциональный мессенджер: сервер, веб-клиент и нативное приложение для macOS.

## Возможности

**Чаты**
- 💬 Личные и групповые чаты
- 📢 Каналы: публикуют только владелец и админы, остальные — подписчики
- 👑 Роли: владелец / админ / участник; назначение админов, добавление и удаление участников, выход из чата
- 📌 Закреплённые сообщения
- 🔇 Отключение уведомлений по чату (mute)
- ✏️ Редактирование названия, описания и аватара группы/канала

**Сообщения**
- ⚡ Доставка в реальном времени (WebSocket) с мгновенным подтверждением
- 🖼 Фото и видео с предпросмотром, 📄 файлы до 50 МБ, 🎤 голосовые сообщения
- ↩️ Ответы (reply) с цитатой и переходом к исходному сообщению
- ➡️ Пересылка сообщений в другие чаты
- 😀 Реакции (👍 ❤️ 🔥 😂 😮 😢 🎉)
- ✓ / ✓✓ Статусы доставки и прочтения, счётчики непрочитанных
- ⌨️ Индикатор «печатает…», 🟢 статусы «в сети / был(а) недавно»
- ✏️ Редактирование и удаление своих сообщений (админ может удалять чужие в группах)
- 📜 История с подгрузкой при прокрутке, черновики по чатам
- 🔍 Глобальный поиск по людям и сообщениям
- 🖱 Отправка файлов перетаскиванием в окно чата

**Звонки**
- 📞 Аудио- и 🎥 видеозвонки 1-на-1 (WebRTC, P2P; в разных сетях за NAT может
  понадобиться свой TURN-сервер)

**Профиль и интерфейс**
- 👤 Профиль: имя, «о себе», аватар
- 🌙 Светлая и тёмная темы
- 🔔 Нативные уведомления и бейдж непрочитанных в доке macOS
- 🔐 Пароли — scrypt, сессии — подписанные HMAC-токены

## Структура

```
messenger/
├── server/    Сервер: Node.js (REST API + WebSocket), SQLite (node:sqlite)
├── web/       Веб-клиент: HTML/CSS/JS без сборки, отдаётся сервером
└── desktop/   Приложение для macOS: Electron + electron-builder
```

Единственная зависимость сервера — пакет `ws`. База данных — встроенный
SQLite из Node.js 22.5+, без нативной компиляции. Файлы хранятся на диске
в `server/data/files/`.

## Запуск сервера и веб-клиента

Требуется Node.js ≥ 22.5.

```bash
cd messenger/server
npm install
npm start
```

Откройте http://localhost:3000 — это веб-клиент. Зарегистрируйте двух
пользователей в разных браузерах (или обычное + приватное окно) и напишите
друг другу.

Переменные окружения:

| Переменная      | По умолчанию       | Назначение                          |
|-----------------|--------------------|-------------------------------------|
| `PORT`          | `3000`             | Порт HTTP/WebSocket                 |
| `HOST`          | `0.0.0.0`          | Адрес для прослушивания             |
| `GRAM_DATA_DIR` | `server/data`      | Каталог базы данных и файлов        |
| `GRAM_SECRET`   | генерируется       | Ключ подписи токенов                |
| `GRAM_WEB_DIR`  | `../web`           | Каталог статики веб-клиента         |

> Для звонков и голосовых сообщений браузеры требуют безопасный контекст:
> работает на `http://localhost` без настройки, для доступа по сети
> поставьте HTTPS-прокси (например, Caddy или nginx с сертификатом).

## Приложение для macOS

Сборка выполняется на Mac (electron-builder собирает .dmg только на macOS):

```bash
cd messenger/desktop
npm install
npm start        # запуск в режиме разработки
npm run dist     # сборка Gram.dmg (arm64 + x64) в desktop/dist/
```

По умолчанию приложение подключается к `http://localhost:3000`.
Адрес сервера меняется через меню **Gram → Адрес сервера…** (⌘,) —
укажите адрес машины, где запущен сервер, например `http://192.168.1.10:3000`.

Особенности macOS-версии:

- скрытый заголовок окна в стиле нативных приложений (hiddenInset);
- бейдж с числом непрочитанных на иконке в доке (mute-чаты не считаются);
- нативные уведомления;
- русифицированное меню, поддержка тёмной темы системы.

## Архитектура

- **REST API** (`/api/*`) — аккаунты, профили, чаты, участники, сообщения,
  файлы, реакции, поиск. Авторизация — `Authorization: Bearer <token>`.
- **Файлы** — `POST /api/upload` (бинарное тело + `X-File-Name`),
  раздача `GET /files/:id` с правильным mime и кэшированием.
- **WebSocket** (`/ws?token=…`) — события в реальном времени: сообщения,
  подтверждения (`ack` по `tempId`), «печатает», статусы, прочтения,
  правки/удаления, обновления чатов, сигналинг звонков (offer/answer/ICE).
- Клиент шлёт текст через WebSocket с оптимистичным отображением; при
  разрыве соединения переключается на REST и переподключается с
  экспоненциальной задержкой.
- Звонки — P2P WebRTC: сервер только пересылает сигнальные сообщения
  между собеседниками.

### Схема БД

`users` → `chats` (`direct`/`group`/`channel`) → `chat_members`
(роль, mute, `last_read` для непрочитанных и галочек ✓✓) →
`messages` (вид: text/image/video/voice/file, ответы, пересылка, мягкое
удаление) + `files` (метаданные, блобы на диске) + `reactions`.
